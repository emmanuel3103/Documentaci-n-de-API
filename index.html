1. Introducción

1.1 Propósito

Este documento describe la API REST utilizada por la aplicación móvil EDI-301. Incluye endpoints, métodos, parámetros, respuestas y ejemplos de uso.

1.2 Alcance

Cubre:

  • Autenticación (JWT).
  • Gestión de usuarios.
  • Familias EDI.
  • Eventos.
  • Publicaciones.
  • Imágenes (perfil y portada).
  • Manejo de errores y paginación.

1.3 Público objetivo

  • Desarrolladores móviles (Flutter).
  • Desarrolladores backend.
  • TI de la Universidad Linda Vista.

1.4 Convenciones generales

  • Formato: JSON en todas las respuestas.
  • Autenticación: `Authorization: Bearer <token>`.
  • Códigos de estado: 200, 201, 400, 401, 403, 404, 500.
  • Base URL QA: https://qa.edi.ulv/api
  • Base URL PROD: https://edi.ulv/api

2. Autenticación y seguridad

POST /auth/login

Autentica al usuario y genera un token JWT.

{
  "email": "usuario@ulv.edu.mx",
  "password": "MiContraseña123"
}

Respuesta 200:

{
  "ok": true,
  "token": "",
  "user": {
    "id": 12,
    "nombre": "Juan Pérez",
    "rol": "HIJO",
    "familiaId": 3
  }
}

GET /auth/me

Devuelve los datos del usuario autenticado.

POST /auth/logout

Opcional: invalida el token actual.

3. Manejo de errores

{
  "ok": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "El campo 'email' es obligatorio"
  },
  "timestamp": "2025-11-24T12:00:00Z"
}

Códigos:

  • 200 OK
  • 201 Created
  • 400 Bad Request
  • 401 Unauthorized
  • 403 Forbidden
  • 404 Not Found
  • 500 Internal Server Error

4. Recursos de la API

4.1 Usuarios

GET /users

Lista usuarios (ADMIN).

{
  "ok": true,
  "data": [
    { "id": 1, "nombre": "Coordinador", "rol": "ADMIN" }
  ],
  "pagination": { "page":1, "limit":20, "total":45 }
}

POST /users

{
  "nombre": "María",
  "email": "maria@ulv.edu.mx",
  "password": "12345678",
  "rol": "PADRE",
  "familiaId": 3
}

4.2 Familias

GET /families

{
  "ok": true,
  "data": [
    {
      "id": 3,
      "nombre": "Familia Esperanza",
      "padreId": 2
    }
  ]
}

GET /families/{id}

{
  "ok": true,
  "family": {
    "id": 3,
    "nombre": "Familia Esperanza",
    "miembros": [
      { "id": 12, "nombre": "Juan", "rol": "HIJO" }
    ]
  }
}

4.3 Publicaciones

GET /posts

{
  "ok": true,
  "data": [
    {
      "id": 10,
      "titulo": "Bienvenida",
      "contenido": "Mensaje...",
      "familiaId": 3
    }
  ]
}

POST /posts

{
  "titulo": "Nueva reunión",
  "contenido": "Viernes 7pm",
  "familiaId": 3
}

4.4 Eventos

GET /events

{
  "ok": true,
  "data": [
    {
      "id": 5,
      "titulo": "Convocatoria",
      "fechaInicio": "2025-09-01T18:00:00Z"
    }
  ]
}

POST /events

{
  "titulo": "Cena",
  "descripcion": "Cierre de semestre",
  "fechaInicio": "2025-11-30T19:00:00Z",
  "fechaFin": "2025-11-30T21:00:00Z",
  "ubicacion": "Casa EDI"
}

4.5 Imágenes y archivos

POST /families/{id}/images

Sube foto de perfil o portada.

Content-Type: multipart/form-data 
{
  "ok": true,
  "url": "https://edi.ulv/img/families/3-cover.jpg"
}

6. Versionado de la API

Se recomienda utilizar rutas versionadas:

https://edi.ulv/api/v1/...

7. Buenas prácticas para clientes

  • Renovar token solo cuando sea necesario.
  • Manejar correctamente 401 / 403.
  • No almacenar contraseñas localmente.
  • Usar reintentos solo en errores de red.
